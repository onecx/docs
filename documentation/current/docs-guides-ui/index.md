# Working on OneCX UIs

This page is the single entry point for working on a OneCX UI. It is aimed at integrating an existing app: the pages below are independent entry points, so follow only the ones you need, in any order, rather than a fixed onboarding sequence. When creating a new app from scratch, work through the setup tiers in order.

* [Required Setup](setup/required/index.html) — the steps an application **must** complete to function in the OneCX shell at all. Complete these first.
* [Recommended Setup](setup/recommended/index.html) — the steps an application **should** complete to behave correctly (styles, translations, and navigation).
* [Features](features/index.html) — the optional platform features an application **may** adopt with no correctness impact if skipped (the former "Optional Setup" tier).
* [Concepts](concepts/index.html) — short, technology-agnostic overviews of the core platform concepts, each linking out to the deeper internal developer docs.
* [Troubleshooting](troubleshooting/index.html) — how to diagnose and resolve common problems when building, integrating, or running a OneCX UI application.
* [Migrating an Existing App](migration/index.html) — the Angular guide for bringing an existing app to OneCX, whether you start from a vanilla app or upgrade an existing OneCX app across library versions.
* [React](react/index.html) — onboarding a React app. A dedicated React integration guide is not yet available; until it lands, start from the React section, which lists the React libraries and integration guidelines.
* [Contribution & Testing](#documentation:onecx-portal-ui-libs:contribution-testing/index.adoc) — how to test a change before opening a pull request, organized by verification scope (local-only, integration, and application-only).
